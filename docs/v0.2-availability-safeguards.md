# Availability and redundancy safeguards — v0.2 research policy

This **experimental** policy extends v0.1 without changing v0.1's behaviour. It is not a validated operational decision system.

## Run the experimental policy

From the repository root:

```powershell
py main.py --policy policy/v0.2.json --output reports/v0.2_results.json --report reports/v0.2_comparison.md
py -m unittest discover -s tests -v
```

The five original synthetic cases are retained. This version adds conditional remediation gates and tests, **not** calibrated risk priorities or new case fixtures. The existing `main.py` default remains v0.1, so choose `--policy policy/v0.2.json` explicitly.

## Decision contract

For `availability_consequence` of **high** or **critical**:

1. Record `OPERATIONAL_AVAILABILITY_REVIEW_REQUIRED` and request approval from an OT operations engineer.
2. Require `availability_impact_review_approved=true` for a patch **proposal**.
3. If `redundancy_verified=true`, allow a proposal subject to all existing patch-readiness and human safety/change gates.
4. If `redundancy_verified=false`, require `downtime_contingency_approved=true` to allow a proposal.
5. If `redundancy_verified="unknown"`, prohibit a patch proposal even if someone marked contingency approved; verify redundancy first.
6. Missing approval fields are interpreted as `"unknown"`, never as `true`.

Both new fields are optional in the input schema for backward compatibility:
- `availability_impact_review_approved`: `true | false | "unknown"`.
- `downtime_contingency_approved`: `true | false | "unknown"`.

For low or medium availability consequences, these additional gates are not applied in this experiment. Other safety gates and patch-readiness checks remain in effect.

**Important:** `PROPOSE_PATCH_IN_APPROVED_WINDOW` is an advisory recommendation for human consideration only. It does not mean that adequate site-specific risk assessment has been performed, that an outage is safe, or that any change has been authorised or executed.

## Experiment boundaries

- v0.2 does not yet model the actual redundancy architecture, recovery testing, impact propagation, or timing of service interruption.
- Approval fields in synthetic fixtures are assertions; real-world approval authenticity is **not** verified.
- No automatic action or integration with PLCs, networks, scanners or patch tools.
- The research policy has not been compared with expert-labelled OT cases.
- Compensating-control evaluation and threat-intelligence provenance remain future work.
- Original v0.1 policy and published source files are preserved for reproducibility.
