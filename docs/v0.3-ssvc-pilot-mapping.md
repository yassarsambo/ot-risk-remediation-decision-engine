# OT-RRDE v0.3 SSVC pilot mapping

**21 November 2026 · Author-proposed mappings awaiting independent criticism**

## Finding

The eight original pilot dossiers provide **0/8 complete input combinations** for the pinned CERT/CC SSVC Deployer priority tree. All eight leave Automatable and Human Impact unresolved. Five also leave Exploitation unresolved because the record of public proof-of-concept checking is incomplete. These gaps define the next evidence-collection task. The original pilot remains useful for examining the OT-RRDE timing change and testing the reviewer rubric.

The mapping in [ssvc_pilot_mapping_v0.3.json](../data/ssvc_pilot_mapping_v0.3.json) records the proposed value, evidence references and reasoning for every decision point. Its values are analyst interpretations of fictional cases. Independent judgement is pending.

OT-RRDE's P1/P2/P3 labels describe when a human should investigate. This SSVC model assigns deployment priority using Defer, Scheduled, Out-of-Cycle or Immediate. The research protocol calls for separate human judgements of these endpoints and compares pair orderings only where the reference judgements agree about the order. The study's deployment-rating question focuses on an applicable, deployable patch. SSVC's wider documented action space also covers mitigation when a remediation is unavailable. ## How the comparison changes the research question

The published SSVC guidance already considers mission and safety, deployed context, controls that alter exposure, and how later changes can invalidate a mitigation. Those concepts establish relevant prior work for OT-RRDE. The experiment should isolate what explicit source provenance and timing checks add to the human decision process, measuring avoidable evidence use, missed urgency and review workload. [Deployer guidance](https://github.com/CERTCC/SSVC/blob/bf3213bc0bd2bf3cf1329c9b48f72d7163a682b1/docs/howto/deployer_tree.md) · [Human Impact](https://github.com/CERTCC/SSVC/blob/bf3213bc0bd2bf3cf1329c9b48f72d7163a682b1/docs/reference/decision_points/human_impact.md)

PILOT-83 is the only urgency difference between the two OT-RRDE policies in this replay. The v0.3 development policy excludes its late EPSS snapshot and assigns P3. All eight candidate actions agree. In PILOT-16, the shared case projection already sets the withdrawn exploitation claim to unknown. The existing engines consume that authored projection, so the replay tests the supplied case fields. A subsequent provenance experiment should explicitly assess how the engine resolves the withdrawal and shared origin of the reports.

## Reproduce the audit

From the repository root, use Python 3.10 or newer.

```sh
python3 scripts/evaluate_ssvc_pilot.py
python3 -m unittest discover -s tests -v
python3 scripts/evaluate_benchmark.py
```

The first command emits JSON with every mapping, default, missing input, native SSVC outcome when fully specified, and both OT-RRDE outputs. The current replay reports eight cases, zero complete SSVC inputs, one case in the protocol's conditional deployment scope, and missing-input counts of eight Automatable, eight Human Impact and five Exploitation.

The Python 3.12 verification passed **55 tests**, including reproduction of every one of the reference table's 72 rows, preservation of unresolved input values, rejection of invalid inputs and duplicate table matches, and maintenance of the existing urgent-review flag.
