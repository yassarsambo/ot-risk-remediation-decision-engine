# How do you review a security issue when the records disagree?

*Yassar Sambo, 23 November 2026*

Imagine you’re reviewing a supplier’s security notice at 10 am. It covers version 4.2 of a gateway. Your equipment register says 4.2, but a maintenance note says 4.3. A corrected register arrives at noon. If a colleague looks back tomorrow, how will they know what information you had at 10?

I built an offline tool for engineers who review security issues in industrial systems. The published version (v0.2.1) uses fictional cases to suggest how soon someone should investigate and what still needs checking before a change. One feature I’m testing for v0.3 looks at a score that predicts how likely attackers are to use a vulnerability. If the record says the score arrived after the review, the tool leaves it out.

I’d like to build a short note that shows what the reviewer knew at the time, where records disagreed and what still needed checking. The people responsible for the equipment would decide whether to make a change.

If you investigate security issues or approve changes, I’d value a general example from a recent review. What did you use, and what worked well? If you had to chase a missing detail, roughly how long did that take? Would a note like this save a step or add paperwork?

A short reply or a 10–15 minute conversation would help. Please leave out confidential details. I’ll ask before quoting you or using your name.

If you’d also like to rate fictional cases independently, message me for the case sheets before reading results elsewhere in the repository. Please mention any results you’ve already seen.
